# Wann Code, wann No-Code?

Dasselbe Mini-RAG lässt sich als Python-Code (wie im Kurs) oder als Flow in einem No-Code-Werkzeug wie Flowise oder Langflow bauen. Beide Wege sind richtig, sie lösen unterschiedliche Probleme.

| Frage | Eher Code | Eher No-Code |
| ----- | --------- | ------------ |
| Wie schnell brauche ich einen Prototyp? | Etwas länger | Sehr schnell |
| Muss ich prüfen und testen können, was passiert? | Ja, jede Zeile ist sichtbar | Nur eingeschränkt |
| Soll es in ein eigenes Programm eingebaut werden? | Ja | Eher nein |
| Arbeitet ein Team, das nicht programmiert, am Ablauf mit? | Nein | Ja |
| Brauche ich eigene Logik, die kein Baustein kann? | Ja | Kaum |
| Muss ich genau wissen, was an das Modell geschickt wird? | Ja | Schwerer sichtbar |

**Faustregel:** Für einen schnellen Versuch oder eine Demo ist No-Code gut. Sobald du prüfen, erweitern oder einbetten musst, brauchst du Code. Auch bei No-Code gilt der 3-Punkte-Quellencheck: Ein bunter Flow macht die Antworten nicht verlässlicher.

Zum Abschlussprojekt (Modul 6): Du darfst beides verwenden. Entscheide mit diesen Fragen und begründe es in einem Satz.
