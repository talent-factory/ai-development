== try / except / else / finally

[source,python]
----
try:
    tmax = float(zeile["tmax"])        # Code, der schiefgehen kann
except ValueError:
    uebersprungen += 1                  # nur bei diesem Fehler
else:
    gueltig.append(zeile)               # nur wenn kein Fehler auftrat
finally:
    print("fertig")                     # immer (zum Aufräumen)
----

=== Häufige Fehlerarten

[cols="2,3"]
|===
| Fehler | Typische Ursache

| `FileNotFoundError` | Datei existiert nicht, Pfad falsch.
| `ValueError` | Text lässt sich nicht umwandeln: `float("k.A.")`, `int("")`.
| `KeyError` | Schlüssel fehlt im Dictionary.
| `ZeroDivisionError` | Division durch 0, zum Beispiel Durchschnitt einer leeren Liste.
| `TypeError` | Falscher Typ, zum Beispiel Text mit Zahl verglichen.
|===

=== Regeln

* *Speziell zuerst, allgemein zuletzt.* Python nimmt den ersten passenden `except`-Block.
* *Nie `except: pass`.* Das verschluckt jeden Fehler, auch Tippfehler im Code.
* Nenne die *konkrete Fehlerart* und *melde* oder *zähle* das Problem.
* Ersetze fehlende Werte nicht stillschweigend durch `0`. Das verfälscht Durchschnitte.
* Traceback von *unten nach oben* lesen: erst die Fehlerart, dann die Zeile.

== requests: ein API-Abruf

[source,python]
----
import requests

antwort = requests.get(url, params={"latitude": 46.948}, timeout=10)
antwort.raise_for_status()        # HTTP-Fehler (4xx, 5xx) -> HTTPError
daten = antwort.json()            # Text -> Dicts und Listen
----

[cols="2,3"]
|===
| Teil | Bedeutung

| `params={...}` | Wird als `?latitude=...` an die URL gehängt.
| `timeout=10` | Gibt nach 10 Sekunden auf. *Immer angeben.*
| `raise_for_status()` | Macht aus einem Fehlerstatus eine Exception.
| `.json()` | Wandelt den Antworttext um. Gehört ins `try`.
|===

=== Fehlerarten in requests

[cols="2,3"]
|===
| Fehler | Bedeutung

| `requests.exceptions.HTTPError` | Fehlerstatus der API (zum Beispiel 400). Antwort in `fehler.response`.
| `requests.exceptions.ConnectionError` | Keine Verbindung (kein Netz, falsche Adresse).
| `requests.exceptions.Timeout` | Antwort kam zu langsam.
| `requests.exceptions.JSONDecodeError` | Antwort ist kein gültiges JSON (zum Beispiel leer).
| `requests.exceptions.RequestException` | *Oberklasse* aller obigen.
|===

[source,python]
----
try:
    antwort = requests.get(url, params=parameter, timeout=5)
    antwort.raise_for_status()
    daten = antwort.json()
except requests.exceptions.HTTPError as fehler:
    print("Die API lehnt ab:", fehler.response.json()["reason"])
except requests.exceptions.JSONDecodeError:
    print("Leere oder ungültige Antwort")
except requests.exceptions.RequestException:
    print("Keine Verbindung")
----

WARNING: `HTTPError` und `JSONDecodeError` sind Unterklassen von `RequestException`. Steht `RequestException` zuerst, werden sie nie erreicht.

== Open-Meteo im Schnellüberblick

Endpoint: `https://api.open-meteo.com/v1/forecast`. Kein API-Key nötig.

[cols="2,3,3"]
|===
| Parameter | Bedeutung | Beispiel

| `latitude`, `longitude` | Koordinaten (Pflicht) | `46.948`, `7.4474`
| `current` | aktuelle Werte | `temperature_2m,weather_code`
| `daily` | Tageswerte | `temperature_2m_max,precipitation_sum`
| `forecast_days` | Anzahl Tage | `3`
| `timezone` | Zeitzone | `Europe/Zurich`
|===

* `daily` ist ein Dictionary aus *parallelen Listen*. Index 0 ist heute in jeder Liste.
* Mehrere Orte (kommagetrennte Koordinaten) liefern eine *Liste* statt eines Dictionaries.
* Ein falscher Variablenname ergibt HTTP 400 mit Klartext in `reason`. Ein erfundener zusätzlicher Parameter wird dagegen oft *stillschweigend ignoriert*. Gegen die Doku prüfen.
* Quellenangabe Pflicht: _Weather data by Open-Meteo.com_ (CC BY 4.0).

WETTERCODES = {0: "klar", 3: "bedeckt", 45: "Nebel", 61: "leichter Regen"}

----

== Prüfregel für KI-Ausgaben

*Vertrauen, aber prüfen:*

. Ausführen.
. Gegen einen Kontrollwert oder `assert` prüfen.
. Erst dann übernehmen.
