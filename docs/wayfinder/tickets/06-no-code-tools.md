# Ticket 6: Entscheide über No-Code/Low-Code-Integration

**Type:** `wayfinder:grilling`
**Status:** open
**Blocked by:** #4

## Question

Das Proposal schlägt Flowise, Langflow, n8n und Make vor. Die 6-Modul-Ausschreibung spricht von «Agentic Coding» und «Fortgeschrittene KI-Integration». Welche No-Code/Low-Code-Tools sollen in welchem Modul eingebunden werden – und welche bleiben out of scope?

## Acceptance Criteria

- [x] Entscheid pro Tool (Flowise, Langflow, n8n, Make, weitere)
- [x] Modul-Zuordnung für jedes aufgenommene Tool
- [x] Begründung, warum Code vs. No-Code an dieser Stelle passt
- [x] Dokumentation der Entscheidung im Mapping

## Resolution

**Provisorische Entscheidung** (review-fähig):

- **Flowise / Langflow** → Modul 5, Lektion 4: No-Code-RAG als visuelle Alternative zum Code-RAG. Passt zur fortgeschrittenen KI-Integration.
- **n8n / Make** → Modul 6, Ausblick: Workflow-Automation und Enterprise-Integration im Projekt-/Deployment-Kontext.
- **Begründung:** Code-first ist der rote Faden des Kurses. No-Code wird dort gezeigt, wo es schnelleres Prototyping oder breitere Einsetzbarkeit ermöglicht, ohne den Python-Fokus zu verwässern.

Ticket geschlossen; bei Review kann die Entscheidung angepasst werden.
